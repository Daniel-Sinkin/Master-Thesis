\section{Summary}\label{sec:summary}

This work examines tensor-network workloads from an HPC perspective in a
preparatory optimisation phase. The current results establish a
profile-guided workflow, validate a set of microbenchmarks and methodology
checks, and identify the dominant levers on A100-class GPUs: launch overhead,
memory-hierarchy efficiency, and occupancy-resource trade-offs. They should be
read as early evidence and infrastructure for later target-specific tuning,
not yet as the final optimisation study.

\section{Limitations}\label{sec:limitations}

The current scope has three deliberate limitations:

\begin{itemize}
  \item physics-specific algorithm derivations and notation are out of scope,
  \item optimisation focus is on Ampere-era kernels and one-node execution,
  \item coverage of workload diversity is bounded by available benchmark traces,
  \item the final workload/kernel set is still being fixed, so the current
    chapter emphasises proxy kernels, microbenchmarks, and methodology
    validation.
\end{itemize}

\section{Future Work}\label{sec:future-work}

Natural continuation points are:

\begin{enumerate}
  \item selecting and characterising the final target kernel/workload set, then
    reapplying the same correctness and profiling workflow to those kernels,
  \item extending the same methodology to Hopper/H100-class hardware while
    preserving comparability with A100 results,
  \item deeper multi-GPU overlap strategies (communication/computation
    pipelining),
  \item automated kernel-configuration search constrained by profiler-derived
    bottleneck models.
\end{enumerate}
